# Supervisor effective context for the local agent

## Scope and requirement

Base: `71c8aa8c904c00d06d0b5afaa2b20c091e732824`. This change repairs one host routing defect. A supervisor-backed GGUF advertised its training context through `variant.contextMax`, even when the running server had a smaller context. The agent profile then derived its context window, output allowance and compaction reserve from the wrong number.

CTX-1 requires the agent to use the running server's effective per-slot capacity. CTX-2 requires unavailable capacity to exclude that agent route without stopping ordinary chat. CTX-3 requires capacity to belong to the current child and model, including stop, replacement and delayed-response cases. CTX-4 preserves authentication, native and remote route policy, the recommended 131072-token launch, output-budget policy and resource floors.

No installation, publication, model load, GPU experiment or interaction with the owner's running app was performed. The 0.6.0 candidate's delivery and actual-model qualification remain separate work.

## Source and design

The primary source inspected on 2026-11-16 is [PrismML's pinned base server-context.cpp at 73bfe6cc](https://github.com/PrismML-Eng/llama.cpp/blob/73bfe6cc485554822f80c473a3c0c4f25e80f41b/tools/server/server-context.cpp#L4128). `get_res_props` assigns `meta.slot_n_ctx` to `default_generation_settings.n_ctx`; `total_slots` is separate. The same source derives slot capacity from `llama_n_ctx_seq` and can cap it to model training capacity. Thus parsing requested `-c` or dividing it by `-np` cannot establish the final usable slot size. This is source inspection, not a new runtime qualification of PrismML 0.4.1.

After health succeeds, the supervisor makes one GET to its own loopback `/props`, using the existing private-memory key or launch serving key. The request has a 1500 ms timeout and rejects redirects. Only a positive safe-integer `default_generation_settings.n_ctx` with a matching resolved `model_path` is accepted. The host neither records the properties body nor adds keys to public status. The numeric result is cached against the exact child object and exposed as `contextCapacity` only while that child is running. Startup, stop and current-child exit clear it; an old response or old exit cannot populate or clear a replacement's value.

`agent-local.mjs` requires this capacity and ignores the former metadata option. `index.mjs` no longer supplies `variant.contextMax`. Unknown capacity produces an explanatory agent-skipped notice and retains the existing plain-chat path. There is no new network call during chat, status reads or metrics polling. A transient probe failure requires an unload/reload to probe again; an idempotent start of the already running process does not re-probe.

The actual supervisor launch path uses `buildArgs`; it does not accept arbitrary command-line text here. No separate interpretation of duplicate or equals-form context flags was added. Effective numeric server properties remain the authority regardless of how a server resolves its flags. Native ready rows and remote API model context handling are unchanged.

## Independent review fix round 1

The independent review identified F1 and F2 as required boundary corrections. F1 concerns the pre-existing health-wait catch: an older startup could call the global stop function and overwrite a replacement's state after its own health request completed. A launch sequence now guards entry to cleanup and its continuation after stopping. Stop invalidates the old sequence. This also preserves genuine early-exit diagnostics after the child exit callback has cleared the child reference. The delayed-health regression completes both an old successful HTTP response and an old transport rejection only after the replacement is running; neither stops or overwrites it.

F2 concerns small but valid measured windows. Supervisor-to-agent admission now uses the existing `localOutputBudget` and `compactionHeadroom` functions and rejects a capacity with no positive space remaining for a prompt after those reserves. The profile functions and their minimums are unchanged. The test exercises measured capacities 1, 2048, 4096 and 4608 through supervisor status and checks the real profile builder's unchanged 4096 output and 512 headroom floors. Status retains the measured number; the unusable agent route is omitted and the plain-chat notice explains unavailable or insufficient capacity. This arithmetic condition does not claim a complete agent prompt fits: system instructions, tools, history and the actual message still require the existing fit checks.
