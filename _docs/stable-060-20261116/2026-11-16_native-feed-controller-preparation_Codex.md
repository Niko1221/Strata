# Native input and component feed controller preparation

This change prepares two execution adapters for Hakua 0.6.0. It does not perform a native or product build, read the production signing key, sign a production package/feed, install, publish, commit or push. The final native profile, final reviewed source commit, actual phase execution and public readback remain the parent controller's responsibility. `releaseQualified=false` is unchanged.

## Requirements and design

The implementation owns only `native-input.py`, `components-feed.py`, `test_native_feed.py` and this report. Source implementation began at `c297453fe1dfe800a71a038f6445c10eeb5234eb`; the independently owned RoPE fix and native resource-profile changes are outside this scope. Both CLIs default to a read-only plan. They register one phase and its argument vector with the existing `release.py` runner, reusing its clean reviewed commit gate, physical checkout checks, fresh attempt reservation, owned Windows Job, RAM/commit/H/C floors of 3/4/10/5 GiB, five compiler jobs, single test concurrency, and final receipt publication. No second process-containment framework is added. Execution is narrowed to physical C main. The credential-free environment comes from the established native guard; user credentials, Python hooks, compiler overrides and `TAURI_CONFIG` are excluded.

Native execution uses only the already configured `H:/Strata/evidence/upstream-sync-20261116/cuda-build`. It requires the portable CUDA sm_120 cache, current vendored ggml and a source-contained resource baseline. It inventories native sources, cache and baseline before/after the production `tools/build_hakua_engine.mjs <build> 5` invocation. That helper builds all targets, performs its version check and executes the configured resource-profile guard. The adapter additionally probes both `strata.exe` and `strata-q36.exe`, validates the builder record against the frozen inputs, and invokes the production packager with its default selector plus explicit includes for the second executable and `native-build.json`. There is no `--tree` or `--allow-lib` bypass. The caller must supply `--min-driver nvidia=VERSION`; no default or untested Windows minimum is inferred.

Only the physical installed CUDA 13.3 `bin/x64` is a library search source. The adapter checks `version.json` for 13.3.1 and records the before/after hashes of installed DLL sources reached by production selection and PE imports. It compares package DLL bytes with those observations and delegates final PE closure to production `package_engine.py --verify`. These are local installed-toolkit observations, not independent publisher hash/signature proof. Bundled local backend runtime DLLs are composed later by the unchanged `release.py component` path; this adapter does not replace them or assume they use the native toolkit version.

Both pre-build and post-build executables/native-build records are copied into the fresh attempt, including on an ordinary builder failure. Builder and packager logs are retained there. Existing failed attempts are never reused. An abrupt Job termination can interrupt the final snapshot; it leaves no final success receipt. The production packager itself removes its transient `.partial` directory on failure; this adapter retains its logs and before/after build evidence and does not alter that production contract.

The unsigned package's external `native-binding.json` is finalized only after the owned Job has succeeded and drained to zero. Its required fields match `verify.mjs`: source commit/root, `releaseQualified=false`, native-build digest and both binary digests. Additional fields bind the successful builder command/log, before/after input inventories, local toolkit observations, outer owned-Job receipt and final phase receipt. The unchanged native verifier is called inside the worker before finalization. Composition, notices, signing, archiving and staging belong to `release.py component` and are not duplicated.

Feed execution requires explicit successful `control-rN/receipt.json` and `component-rN/receipt.json` paths and expected SHA-256 values from the same final reviewed commit. It checks their successful drained Jobs, rehashes the assets and entry files, validates exact flat membership, archive size/hash, original Control archive and payload, signed component payload/manifest and production signature against bundled keys. It copies assets and entries only to a fresh `feed-rN`. The production feed CLI is called with `build-feed`, the canonical external key, and explicit `--no-dsv41-carry`; signer output is suppressed. Production `verify-feed` then checks bundled trust. No upstream DeepSeek engine, model or app updater member is fabricated or carried.

The predecessor is an explicit local path plus expected SHA-256, compared with an anonymous bounded read of `https://github.com/zapabob/Strata/releases/latest/download/strata-feed.json` and its detached signature. Production signature parsing and the stable channel are required. The successor sequence must exceed the actually observed source-side sequence; no historical 0.5.9 sequence is assumed current. The same source-side predecessor is checked again before successful phase completion. Publication must independently check it again because this preparation cannot lock GitHub state.
