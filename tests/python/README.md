# PLE parity provisioning (bench fixtures + artifact oracles)

`src/kernels/ple_parity.cpp` is a three-oracle test.  Parts A (the n-gram hash)
needs nothing but its own generated vectors.  Parts B and C need artifacts that
cannot live in this repository:

* Part B (the PLE table read) reads the artifact's GGUF at runtime — point
  `STRATA_PLE_TEST_GGUF` at the shard carrying the table tensor.
* Part C (the PLE block) reads a `ple_in.bin` / `ple_out.bin` capture of ggml's
  own graph execution.  The capture carries full-size dequantized f32 weights
  (>100 MB — over GitHub's per-file limit), so it cannot be committed; it is
  machine-local.  Part C also cross-checks the capture's `ple_key` against the
  dense pack's codes at region offsets from `ple_oracle_vectors.inc`, which are
  offsets into a SPECIFIC artifact's pack (that include is per-artifact too).

## What is missing from this tree, and why the configure step does not lie

The original supply chain that produced both artifacts is not in the tree:

* `ple_layer_xcheck.cpp` — the ggml-side capture that produced
  `bench/micro/ple_in.bin` / `ple_out.bin` (referenced by
  `src/kernels/ple_parity.cpp` part C's comment; never committed).
* `tests/python/gen_ple_oracle.py` — the generator named in
  `ple_oracle_vectors.inc`'s own header ("GENERATED by tests/python/gen_ple_oracle.py").
* `ref/ngram.py` — the hash reference the hash-case vectors cite.

Until the author re-adds the capture and oracle generators, the provision path
below cannot be completed from this tree alone; a run without the inputs is a
configure-time "NOT ADDED" with the reason, not a red suite.

## Provisioning, as the CMake expects it

1. Obtain `bench/micro/ple_in.bin` and `bench/micro/ple_out.bin` from the
   author's tree (or regenerate with a re-added capture tool).  Put both under
   `bench/micro/` (override with `-DSTRATA_PLE_FIXTURE_DIR=`).
2. Configure with the artifact the oracle include was generated for:
   `-DSTRATA_PLE_TEST_GGUF=<shard-with-the-table>` and
   `-DSTRATA_PLE_TEST_PACK=<dir-with-dense.bin>`.  `ple_parity` hard-fails
   inside itself if either does not match (wrong row count, pack smaller than
   the offsets require, fixture geometry unexpected) — a corrupt fixture is a
   loud failure, not a green line.

With both steps done, `ctest -R ple_parity` runs parts A (hash), B (table) and
C (block) against real artifacts.  A clone that skips this provisioning has no
`ple_parity` test at all — see CMakeLists.txt at the ple_parity block.

## The capture format, for who re-adds the generator

`load_capture` in ple_parity.cpp is the only reader; the layout in full is
there.  The oracle side of part C tolerates relative 1e-2 per stage, and the
f32 host reference 1e-4 — the bar is strict but not bitwise.
