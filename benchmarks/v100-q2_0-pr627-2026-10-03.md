# V100: selected changes from upstream PR 627

## Result

The selected changes reduce kernel time on this machine. The model tests do **not** show a material prefill throughput increase. Decode results vary between runs. Do not use these results to claim an end-to-end decode increase.

Source: [upstream PR 627](https://github.com/Niko1221/Strata/pull/627), revision `bf4c315`. Fork baseline: `53ec8b0` (v0.1.36). The candidate includes only the int8 KV gather and the GDN recurrence changes, with parity tests.

| Kernel workload | Baseline | Candidate | Result |
| --- | ---: | ---: | --- |
| Int8 KV gather, 32,768-cell pool, 2,051 selected cells | 16.19 / 16.30 us | 14.62 / 14.68 us | About 10% less time; bitwise parity |
| GDN prompt recurrence, 4,096 tokens | 4.2288 ms | 3.9343 ms | 7.0% less time; different FP32 sum order |

The gather uses eight codes per thread. It uses the original four-code path when the pointer alignment does not permit the wider loads and stores. The original path still requires 4-byte code alignment and 8-byte scratch alignment.

The GDN kernel divides each long sum into four accumulators. It is enabled by default only on compute capability 7.0. Set `STRATA_GDN_REC_FAST=0` to use the original pipelined kernel. Set it to `1` to select the fast kernel. `STRATA_GDN_REC_HEADS` and `STRATA_GDN_PIPELINE=0` retain their existing precedence. Other GPU architectures use the original path unless the fast path is explicitly selected.

## Model test

Hardware: two Tesla V100-PCIE-16GB cards, 175 W power limits, PCIe PHB topology without NVLink. During the inspection, GPU 0 reported Gen3 x4 and GPU 1 reported Gen3 x16. CUDA 12.8, Release build, architecture 70.

Model: Qwen3.8-Flash-Next GSQ-RCO Q2_0, native expert pack. Both builds use the current service settings: two GPUs, layer split 20, automatic expert cache and prefill, int8 KV, speculation window 8, minimum acceptance probability 0.70, MTP, vision reservation, 700 MiB VRAM reserve, maximum context 524,288, and YaRN scale 2. `STRATA_EXPERT_PAIR=1` is unchanged.

The test order was baseline A, candidate A, candidate B, baseline B. Each arm includes calibration and three fresh prompts at each size. Arm A uses seed 627 and 128 output tokens. Arm B uses seed 628 and 256 output tokens. Each size completes the full output budget. Every measured row reports zero reused prompt tokens. The engine reports the throughput; client wall time is not used as throughput. Engine restarts precede baseline A, candidate A, and baseline B. Candidate B follows candidate A without a restart. There is no fixed temperature gate. These are small paired samples, not a statistical guarantee.

Medians, tokens per second:

| Arm | Prompt size | Baseline prefill | Candidate prefill | Baseline decode | Candidate decode |
| --- | --- | ---: | ---: | ---: | ---: |
| A | 4K | 708.4 | 709.1 | 72.7 | 61.8 |
| A | 32K | 1674.5 | 1676.3 | 62.9 | 65.1 |
| B | 4K | 706.4 | 707.7 | 71.2 | 70.4 |
| B | 32K | 1666.4 | 1667.4 | 59.9 | 60.6 |

Prefill changes are less than 0.2%. The lower 4K decode result in arm A is not reproduced at the same magnitude in arm B. No reliable decode increase is established. The kernel gains do not remove the expert-bandwidth limit. Raw throughput rows are in [the result directory](../bench/results/2026-10-03-v100-pr627/).

## Correctness

- `kv_q8_parity`: passed. Includes bitwise host dequantization checks and a deliberately misaligned code pool that selects the four-code fallback.
- `prefill_gdn_parity`: passed at 1, 128, and 4,096 tokens. Both paths must produce finite FP32 output, state, and FP16 output. Relative-to-scale limits are 1e-4 for output, 1e-5 for state, and 2e-3 for FP16 output.
- At 4,096 tokens, the numerical smoke measured FP32 output error 1.778e-5 of reference scale and state error 3.353e-7. FP16 output error was 4.042e-4 of reference scale. This is not bitwise equivalence. Small numerical changes can change generated text.
- Existing decode `gdn_parity`: passed.
- Candidate needle recall: six of six passed at 1K and 32K, with depths 10%, 50%, and 90%. Baseline checks at 50% passed at both sizes.
- Candidate OpenAI conversation and native tool diagnostics: five of five passed.
- Gather and prefill recurrence parity also passed on GPU 1 with the model service stopped. An earlier GPU 1 recurrence test with the service loaded failed with insufficient VRAM. Stop the model before the isolated GPU tests.

## Changes not imported

The fork already has Volta tensor-core prompt attention and the BF16-to-FP16 GEMM path. The PR's QPN8 expert path does not serve this native Q2_0 pack. Its NVLink handoff measurements do not apply to this PCIe machine. The chunked GDN path is reported slower by the PR author and is not imported. The separate grouped-attention implementation and non-native GEMV fusions are not imported; this report does not claim measurements for those kernels. The fork already batches verification attention, but this does not prove that the separate grouped kernel has no benefit.

## Reproduction

Build baseline and candidate in separate directories with CUDA 12.8:

```sh
cmake -S "$SOURCE" -B "$BUILD" -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_CUDA_COMPILER=/usr/local/cuda-12.8/bin/nvcc \
  -DCMAKE_CUDA_ARCHITECTURES=70 -DSTRATA_ENABLE_CUDA=ON \
  -DSTRATA_BUILD_TESTS=ON
cmake --build "$BUILD" --target strata kv_q8_parity prefill_gdn_parity -j 8
ctest --test-dir "$BUILD" -R '^(kv_q8_parity|gdn_parity|prefill_gdn_parity)$' --output-on-failure
"$BUILD/kv_q8_parity" --bench
```

The baseline has no `prefill_gdn_parity` target. For a matched gather comparison, compile the candidate `kv_q8_parity.cpp` against the baseline kernel library. Keep the model configuration identical and change only the engine executable. Use the repository virtual environment:

```sh
.venv/bin/python bench/run_v100_bench.py --model-gguf "$MODEL_GGUF" \
  --targets 4096,32768 --seed 627 --repeats 3 --max-tokens 128 --out "$OUT"
```

Repeat with seed 628 and 256 output tokens. Store private model paths and authentication only in the local configuration. The original service and installed engine are restored after the test. No candidate binary replaces the installed engine.
