# V100: prompt attention from upstream PR 600

## Decision

Import the Volta prompt kernel from [upstream PR 600](https://github.com/Niko1221/Strata/pull/600), kernel commit `ee0843da07ee8da96fa0b5afebfdd8dde6c0b587`. The fork already has tensor-core prompt attention. This change improves that existing kernel; it does not add a feature that the fork lacked.

Fork baseline: `1026dff`, with PR 15 merged. The candidate uses all four independent matrix operations of Volta's `mma.m8n8k4`. The earlier fork kernel uses only two. The candidate divides the score product among four dimension groups and adds the partial sums in a fixed order. Query and probability values retain their high/low FP16 split and FP32 accumulation.

The new default applies only to compute capability 7.0 through 7.4. Turing, Ampere, and HIP dispatch retain their existing paths. Int8, FP16, and hybrid K8V4 KV are supported. The fork's Q4-only KV refusal is unchanged. Shared-memory opt-in is tracked per device and per KV mode for layer-split use.

The existing `STRATA_PROMPT_ATTN_V1` control still selects the original int8 tensor-core kernel on Volta. `STRATA_PROMPT_ATTN_OLD=1` remains the prompt-path FP32 fallback control. These are different reference paths. No new runtime variable is required.

## Kernel measurements

The baseline is the **fork's existing tensor-core kernel**, not the slower FP32 reference printed as the first timing in `qsa_prompt_attn_parity`.

Context: 32,768 cells. Prompt chunk: 2,048 queries. CUDA 12.8, Release, architecture 70. Post-reboot GPU 0 measurements:

| KV | Baseline fork kernel | Candidate | Less time |
| --- | ---: | ---: | ---: |
| Int8 | 19.463 ms | 14.041 ms | 27.9% |
| FP16 | 36.200 ms | 28.960 ms | 20.0% |

A later final-build run measured 13.782 ms for the default int8 path and 19.509 ms with `STRATA_PROMPT_ATTN_V1=1`. This also exercises the retained control. GPU 1 measured 13.998 ms for the candidate int8 path and 29.061 ms for FP16.

Against the FP64 reference, maximum absolute error at 32K is 5.08e-6 for candidate int8, compared with 5.56e-6 for the earlier fork kernel. FP16 error is 5.29e-6 for both. Output scale is about 3.6. Both paths pass the existing accuracy gates. They are **not bitwise equivalent**. Small changes can change generated text and speculative acceptance. These checks do not establish unchanged perplexity or long-generation quality.

## Model measurements

All primary rows below were repeated after a machine reboot. The earlier temporary build and result files were lost. The recovered kernel and results are stored in a persistent worktree.

Hardware and software:

- Two Tesla V100-PCIE-16GB GPUs, 175 W power limits, PCIe topology without NVLink.
- AMD Ryzen 5 3600, six cores and twelve threads; 46 GiB RAM reported by the OS.
- Portable T7 and Kingston OM8PDP3256B-AI1 SSDs. Expert weights are resident in RAM during the measured requests.
- Linux kernel 7.0.0-34-generic, NVIDIA driver 580.178.04, CUDA 12.8.
- Both builds use the same local ggml checkout and Release compiler options.

Model: Qwen3.8-Flash-Next GSQ-RCO Q2_0, native expert pack. Runtime settings are unchanged: GPUs 0 and 1, layer split 20, automatic expert cache and prefill, int8 KV, speculation window 8, minimum acceptance probability 0.70, MTP, vision reservation, 700 MiB VRAM reserve, maximum context 524,288, YaRN scale 2, and `STRATA_EXPERT_PAIR=1`.

The order is baseline A, baseline B, a baseline long-context probe, candidate A, candidate B, and a candidate long-context probe. A uses seed 540; B uses seed 541. Each short-context arm includes calibration and three fresh prompts per size. Each row has zero reused prompt tokens and completes 256 output tokens. The baseline arms run against the normal service. Candidate arms use the same wrapper and private model arguments with only the engine executable changed. There is no fixed temperature gate for the 4K/32K arms. Throughput comes from the engine, not client wall time.

Medians, tokens per second:

| Arm | Prompt | Baseline prefill | Candidate prefill | Prefill change | Baseline decode | Candidate decode |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| A | 4K | 707.9 | 717.2 | +1.3% | 63.7 | 64.1 |
| A | 32K | 1673.6 | 1716.0 | +2.5% | 63.4 | 63.4 |
| B | 4K | 706.2 | 715.6 | +1.3% | 69.4 | 67.0 |
| B | 32K | 1662.0 | 1711.2 | +3.0% | 62.4 | 66.3 |

Prefill improves in both arms. These small samples do not guarantee the same gain on other workloads. The upstream 15–18% headline is against an FP32 prompt fallback, which this fork had already replaced. No reliable decode improvement is established. The decode kernel is unchanged, but different prompt numerics and timing-dependent expert admission can change generation and MTP acceptance.

### Cooled long-context probe

Both probes use seed 600, one fresh 131,063-token prompt, and 128 output tokens. Each starts only after both GPUs are at or below 50 C. Baseline starting temperatures are 45/46 C; candidate temperatures are 50/50 C. Baseline runs after its A/B arms; candidate runs after a fresh engine start. Expert admission is automatic, not frozen. This is one pair, not a statistical result.

| Prompt | Baseline prefill | Candidate prefill | Prefill change | Baseline decode | Candidate decode |
| --- | ---: | ---: | ---: | ---: | ---: |
| 128K | 1935.7 | 1991.1 | +2.9% | 56.8 | 50.0 |

The lower candidate decode result is included; do not infer a decode gain from this probe. Recorded peak temperatures are 62/69 C for baseline and 65/71 C for candidate. Raw thermal samples are included. Earlier uncontrolled back-to-back 128K probes were unstable; one candidate run reached 84 C and SM clock fell to 570 MHz. Those lost temporary runs are not used in the primary comparison.

Raw model rows, thermal samples, and the kernel summary are in [the result directory](../bench/results/2026-10-03-v100-pr600/).

## Verification

- Release sm_70 engine build: passed.
- `qsa_prompt_attn_parity`: passed on both GPUs for int8 and FP16 at 32K, and int8 at 1,500 and 2,100 cells.
- `kv_hybrid_parity`: passed on both GPUs, including K8V4 prompt attention.
- Final default and `STRATA_PROMPT_ATTN_V1=1` parity runs: passed. The explicit control selects the earlier int8 kernel.
- Candidate needle recall: seven of seven passed. Six checks use 1K/32K at depths 10%, 50%, and 90%. The `128k` label check at 50% contains 123,099 actual prompt tokens.
- Candidate OpenAI conversation and native tool diagnostics: five of five passed.
- Read-only kernel review found no concrete introduced correctness defect.

Only V100 hardware was exercised. Other architectures retain their source dispatch, but this report does not claim hardware verification on them. The candidate does not replace the installed service binary. The normal boot-managed service is restored after testing.

## Reproduction

Build both revisions with the same compiler and ggml source. Stop the model before isolated GPU parity tests.

```sh
cmake -S "$SOURCE" -B "$BUILD" -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_CUDA_COMPILER=/usr/local/cuda-12.8/bin/nvcc \
  -DCMAKE_CUDA_ARCHITECTURES=70 -DSTRATA_ENABLE_CUDA=ON \
  -DSTRATA_BUILD_TESTS=ON -DSTRATA_PARITY_PROMPT_ATTN=ON \
  -DSTRATA_GGML_DIR="$GGML_SOURCE"
cmake --build "$BUILD" --target strata qsa_prompt_attn_parity kv_hybrid_parity -j 8
"$BUILD/qsa_prompt_attn_parity"
"$BUILD/kv_hybrid_parity"
STRATA_PROMPT_ATTN_V1=1 "$BUILD/qsa_prompt_attn_parity"
```

For the baseline kernel measurement, compile the same parity client against the baseline kernel library. For model measurements, change only the executable in the private service configuration:

```sh
.venv/bin/python bench/run_v100_bench.py --model-gguf "$MODEL_GGUF" \
  --targets 4096,32768 --seed 540 --repeats 3 --max-tokens 256 --out "$OUT"
```

Repeat with seed 541. For the cooled probe, use `--targets 131072 --seed 600 --repeats 1 --max-tokens 128` after both GPUs cool to at most 50 C. Record temperature and clocks through the request. Keep private model paths and authentication out of published results.
