# V100: decode attention from upstream PR 540

## Decision

Import the attention change from [upstream PR 540](https://github.com/Niko1221/Strata/pull/540), head `d9cfcb1ab13e8a468bc4b30b6cf3c6f5bf50a7a5`. Do not import its BF16 GEMM change. The fork already converts BF16 weights to FP16 for Volta GEMMs and produces FP16 activation images. Importing the upstream operand conversion into that path would convert an already-FP16 input as if it were BF16.

Fork baseline: `1026dff`, with PR 15 merged. The candidate changes only `src/kernels/cuda/qsa_decode_attn.cu`. It reduces score-reduction shuffles and query shared-memory reads. The value loop loads four cells together but accumulates them in the original order. Probabilities use the query storage after its last read, so shared-memory use does not increase. The existing hybrid KV path remains available.

## Kernel measurements

Matched baseline and candidate harnesses use the actual attention source, CUDA 12.8, `-O3`, and `sm_70`. The int8 workload selects 2,051 cells from a 32K pool.

| GPU | Attention call | Baseline, us | Candidate, us | Less time |
| --- | --- | ---: | ---: | ---: |
| 0 | Decode step, M=1 | 52.90 | 31.13 | 41.2% |
| 0 | Verify batch, M=8 | 180.42 | 111.85 | 38.0% |
| 1 | Decode step, M=1 | 58.15 | 33.41 | 42.5% |
| 1 | Verify batch, M=8 | 196.28 | 119.22 | 39.3% |

A direct byte comparison passed on both GPUs for 13 cases per GPU. Cases include M=1 and M=8; widths 2, 63, 64, 65, and 2,051; masked pages at the start, middle, and last partial chunk; and int8, q4, and hybrid K8V4 modes. This comparison establishes bitwise equality for the tested inputs, not all possible inputs.

## Model measurements

Hardware: two Tesla V100-PCIE-16GB cards, 175 W power limits, PCIe topology without NVLink. CUDA 12.8, Release build, architecture 70. Baseline and candidate use the same local ggml source checkout and build options.

Model: Qwen3.8-Flash-Next GSQ-RCO Q2_0 with native experts. Runtime settings are unchanged: GPUs 0 and 1, layer split 20, automatic expert cache and prefill, int8 KV, speculation window 8, minimum acceptance probability 0.70, MTP, vision reservation, 700 MiB VRAM reserve, maximum context 524,288, YaRN scale 2, and `STRATA_EXPERT_PAIR=1`.

The order is baseline A, candidate A, candidate B, baseline B. Engines start fresh before baseline A, candidate A, and baseline B. Candidate B follows candidate A. Each arm includes calibration and three fresh prompts per size. A uses seed 540; B uses seed 541. Every row reports zero reused tokens and completes 256 output tokens. Throughput comes from engine timings. There is no fixed temperature gate.

Medians, tokens per second:

| Arm | Prompt | Baseline prefill | Candidate prefill | Baseline decode | Candidate decode | Decode change |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| A | 4K | 709.4 | 708.2 | 63.4 | 65.2 | +2.8% |
| A | 32K | 1675.0 | 1674.5 | 64.2 | 66.8 | +4.0% |
| B | 4K | 707.2 | 706.7 | 63.9 | 64.9 | +1.6% |
| B | 32K | 1666.3 | 1666.1 | 61.6 | 65.1 | +5.7% |

All four paired medians improve decode. These small samples do not guarantee that gain on other prompts or settings. Timing-dependent expert-cache admission and MTP acceptance can change decode speed. Prefill is unchanged within 0.2%. The fork uses a separate tensor-core prompt kernel, so the upstream prefill headline does not apply here.

Raw throughput rows are in [the result directory](../bench/results/2026-10-03-v100-pr540/).

## Verification

- CUDA Release engine build: passed.
- `kv_stream_parity` and `kv_hybrid_parity`: passed on both GPUs.
- Direct baseline/candidate kernel byte comparison: 13 of 13 passed on each GPU.
- Candidate needle recall: six of six passed at 1K and 32K, at depths 10%, 50%, and 90%.
- Candidate OpenAI conversation and native tool diagnostics: five of five passed.

Only V100 hardware was tested. The upstream rewrite also applies to other supported GPUs; this report does not establish its speed on them.

## Reproduction

Build both sources with the same compiler and ggml checkout. Stop the model before isolated GPU parity tests.

```sh
cmake -S "$SOURCE" -B "$BUILD" -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_CUDA_COMPILER=/usr/local/cuda-12.8/bin/nvcc \
  -DCMAKE_CUDA_ARCHITECTURES=70 -DSTRATA_ENABLE_CUDA=ON \
  -DSTRATA_BUILD_TESTS=ON -DSTRATA_GGML_DIR="$GGML_SOURCE"
cmake --build "$BUILD" --target strata kv_stream_parity kv_hybrid_parity -j 8
ctest --test-dir "$BUILD" -R '^(kv_stream_parity|kv_hybrid_parity)$' --output-on-failure
```

Change only the engine executable in the private service configuration. Use the repository virtual environment for the benchmark:

```sh
.venv/bin/python bench/run_v100_bench.py --model-gguf "$MODEL_GGUF" \
  --targets 4096,32768 --seed 540 --repeats 3 --max-tokens 256 --out "$OUT"
```

Repeat with seed 541. Keep authentication and model paths in local configuration only. The original installed engine is not replaced by the candidate.
