\begin{abstract}
The exact-cell KV window is an opt-in memory/accuracy trade-off for Strata: \texttt{--kv q4lm8v} paired with \texttt{STRATA\_KV\_WINDOW=1} (shape $S{=}256, R{=}64$, \texttt{--prefill auto} capped at $B{=}6144$) yields a measured operating point of 5.29 bit/cell ($\sim$1.016\,MiB at 128K) versus 8.00 bit/cell for \texttt{int8} ($\sim$1.584\,MiB at 128K). \texttt{int8} remains the quality default. This paper documents the design of the window, the development decisions made while hardening it (A1--A5), and the validation methodology. All window logic is gated behind \texttt{qsa\_kv\_win()}. Across 8/8 runs the \texttt{int8} default dump-logits SHA is byte-identical (\texttt{A014F504\ldots BA052}), the window stays opt-in, and compatibility edges (free-ring auto chunk, streaming interaction, grid stability, empty/tag initialization) are closed without changing the default path. AMD HIP (RX 9060 XT, Windows, ROCm 7.1) is tested; CUDA/SYCL build checks are requested as review gates. A full cell$\rightarrow$row parity test is planned as follow-up.
\end{abstract}

\section{Introduction}

Strata's KV cache supports several quantization schemes. \texttt{q4lm8v} introduces an \emph{exact-cell window}: a small resident ring of recent cells is kept in a higher-precision/exact form, while older cells use the compressed representation. The goal is to recover accuracy for the most recent context without paying the full cost of keeping the entire KV at \texttt{int8}. 

The implementation was functional in principle, but several integration points could silently fail: the host-side prefill chunking, the interaction with KV streaming/residency, per-state grid selection, and the semantics of uninitialized/empty ring entries. These were treated as correctness issues (not performance) and fixed behind the same opt-in flag with no change to the default \texttt{int8} path.

The window is configured by $S$ (window size), $R$ (recent/exact ring shape), and batch/chunk $B$ (governed by \texttt{--prefill}). With \texttt{--prefill auto}, the effective batch is capped to $B{=}6144$ in windowed runs for correctness (see A1).

\subsection{Architecture notes}
\begin{itemize}[leftmargin=*,noitemsep,topsep=2pt]
\item \textbf{Gating:} Window code paths are only active when \texttt{qsa\_kv\_win()} is true / \texttt{st.k\_win != nullptr}.
\item \textbf{Recent cells:} A side pool holds exact/recent cells accessed through window helpers (\texttt{win\_row\_of}, read via \texttt{qsa\_win\_slot}).
\item \textbf{Residency:} The window's recent cells must remain resident. This is a property of the memory plan, not a tunable that can be arbitrarily combined with streaming (see A2).
\item \textbf{Grid:} The (S,R,B) grid defines the window geometry; stability across states is required (see A3-lite).
\item \textbf{Tags:} Ring entries use tags to distinguish empty/stale entries from valid exact cells (see A5).
\end{itemize}

\textbf{Key principle:} when there is any risk of silent misread (exact promised but quantized read), we prefer a loud refusal or an invariant/assert over guessing. Where setup can prevent bad configs, we prevent them there; where configs can be hand-edited, the engine enforces the contract.

\section{Validation Methodology and Results}

\subsection{Methodology details}
\begin{itemize}[leftmargin=*,noitemsep,topsep=2pt]
\item \textbf{Byte-identity:} dump-logits/STRATA\_LOGPOS SHA of \texttt{int8} default is the regression gate. All changes gated behind \texttt{qsa\_kv\_win()}.
\item \textbf{Probes:} targeted probes reproduce the former crash (B) and edge cases (C: explicit ring) before/after fixes.
\item \textbf{A/B:} 4K segments, rounds 1--4, old/new interleaved where possible. Window measured on same segment sets for direct comparison.
\item \textbf{Noise control:} single GPU job, quiet machine. Timing not reported as comparative; quality/SHA are.
\end{itemize}

\section{Build Coverage, Risks, and Follow-up}

\subsection{Build coverage}
\begin{itemize}[leftmargin=*,noitemsep,topsep=2pt]
\item \textbf{Tested:} AMD HIP, RX 9060 XT 16\,GB, Windows 11, ROCm 7.1 (built with \texttt{vcvars64}, target \texttt{strata}).
\item \textbf{Not tested:} NVIDIA CUDA (nvcc) and Intel SYCL (dpcpp) — no suitable GPUs/toolkits locally. 
\item \textbf{Notes:} Changes are backend-agnostic (globals, arg checks, setup Python, memset value). \texttt{q4lm8v} is not offered on SYCL (\texttt{WINDOW\_KV}=False) so window paths are dead there but should compile. CUDA/SYCL build verification requested as part of review. Uncommitted unrelated workarounds (\texttt{src/core/mtp.cpp}, \texttt{src/kernels/cuda/iq\_kernels.cu}) not included.
\end{itemize}

\subsection{Known limitations / follow-up}
The teacher-forced log-prob measurements cover one read path. The full cell$\rightarrow$row contract must be validated across all shapes:
\begin{itemize}[leftmargin=*,noitemsep,topsep=2pt]
\item Writer \texttt{win\_row\_of} (\texttt{kv\_q4.cu:391}) $\leftrightarrow$ reader \texttt{qsa\_win\_slot} (\texttt{qsa\_decode\_attn.hpp:73}, host \texttt{:93})
\item Ring wrap after scrolling past R rows
\item Stale-tag $\to$ quantized fallback
\item Sink rows (cell-addressed, not ring rows)
\item Batch-boundary shapes (\texttt{STRATA\_KV\_WINDOW\_BATCH} vs \texttt{--prefill}, A1 cap)
\item Empty-tag on zeroed memory (A5)
\end{itemize}
A follow-up PR will add an engine-level parity check (dump every window row at write time, re-read via \texttt{qsa\_win\_slot} on each shape). Meanwhile window stays opt-in and \texttt{int8} default remains byte-identical.

\section{Conclusion}

Hardening \texttt{q4lm8v} was primarily an exercise in preventing silent failures at integration boundaries. By combining setup-side prevention with engine-side enforcement, freezing state invariants, and correcting initialization semantics, the window can safely provide 5.29 bit/cell at 128K while keeping \texttt{int8} as the byte-identical quality default. The evidence (byte identity, probes, refusal tests, KL/top-1) supports this, with CUDA/SYCL build coverage and full cell$\rightarrow$row parity identified as the remaining validation gates.
