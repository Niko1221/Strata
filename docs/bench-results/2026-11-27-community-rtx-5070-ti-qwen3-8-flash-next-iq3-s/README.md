# Community benchmark: NVIDIA GeForce RTX 5070 Ti 16 GB, Strata 0.2.22

Measured on 2026-11-27 by wodaco17-bit. One RTX 5070 Ti 16 GB running
Qwen3.8-Flash-Next IQ3_S at 131,072-token context. The engine was restarted at 17:23 and the
community suite of `tools/strata_bench.py --long` ran against this fresh instance at ~17:45
(three runs per test, medians with ranges; total suite time 114 s), followed by a 6-case
needle recall check on the same instance. Other programs, including the browser, were closed
for the run. Startup evidence: `engine-log-excerpt.txt` (sanitized engine log of this exact
instance).

## Hardware and software

- GPU: NVIDIA GeForce RTX 5070 Ti, 16 GiB VRAM (16,303 MiB driver-reported). Driver 621.40,
  CUDA 13.5. Power limit 300 W.
- PCIe link: gen4 x16. The engine's startup probe on this instance reported
  `PCIe probe 28.4 GB/s -> pcie_frac 0.55`; this is the engine's raw probe value, not an
  independent bandwidth measurement.
- CPU: AMD Ryzen 7 5700X3D (8 cores / 16 threads). Installed RAM: 127.9 GiB.
- Storage: ADATA SX6000PNP NVMe; Samsung 870 EVO 500 GB SATA; two Kingston SATA SSDs
  (SV300S37A120G, SA400S37480G).
- OS: Windows 11 (10.0.26200).
- Strata desktop app 0.2.22, release build; engine 0.1.69 (`0.1.69-windows-x86_64-cuda-cuda13`).
- Background workloads: browser and other user programs closed for the run; no other
  inference clients. GPU state during the suite was not separately recorded (no clock
  capture this time).

## Model and configuration

- Model: Qwen3.8-Flash-Next; quantization: IQ3_S.
- Source repository: `ISTA-DASLab/Qwen3.8-Flash-Next-GSQ-RCO-GGUF` (repository revision not recorded).
- GGUF files (from the pack's `conversions.json`):
  `Qwen3.8-Flash-Next-GSQ-RCO-IQ3_S-00001-of-00002.gguf` (54,817,524,224 bytes) and
  `Qwen3.8-Flash-Next-GSQ-RCO-IQ3_S-00002-of-00002.gguf` (28,800,138,432 bytes).
- Pack `iq3_s` prepared by the engine's `tools/iq_pack.py`; expert profile `expert-profile.bin`
  was generated by the Strata app's setup on 2026-11-25. On 2026-11-26 the app's autotuner ran
  87 minutes and reported the current settings as already the fastest (`IQ3_S 128K – Full speed`);
  it changed nothing, and the profile file is unchanged since 2026-11-25.
- Runtime model modification: a refusal-direction control vector was active in the server command
  line for all runs in this report: `Huihui-Qwen3.8-Flash-Next-refusal-direction-r.gguf`,
  scale 1.0, layers 4–44, mode `project`, direction `per-layer` (engine log: "41 steered").
  File revision not recorded. Speed is not expected to depend on it, but the model's behaviour
  is modified; treat quality comparisons to unmodified Flash-Next accordingly.
- Vision: enabled (`--vision`, mmproj `Qwen3.8-Flash-Next-BF16.gguf`); no vision task was measured.
- Engine-reported state for this instance: expert cache 3,474 slots (6.65 GiB of VRAM,

## Method

`python tools/strata_bench.py --long --url http://127.0.0.1:18500 --api-key …` against the HTTP
API of the fresh instance; model loading is not timed. One warm-up chat and a 1K prompt are
discarded first. Every prompt starts with a unique tag, so the conversation cache cannot help
the fresh-prompt tests (the agent session is the opposite case: it deliberately reuses the
conversation). This was the first benchmark suite against this instance. Thinking off and
temperature 0 are the benchmark tool's request-level defaults for this suite; they are not part
of the server command line. Speeds are the engine's own timings; first-token times are measured
by the client over HTTP.

- short chat: the three questions of `tools/ab_engine.py`, up to 100 new tokens; the three
  questions run three times each (9 requests total)
- 4K / 16K prompts: generated word lists sized by a calibration request, 24 new tokens, 3 fresh prompts each
- 32K prompt (--long): same construction at about 32,768 tokens, 3 fresh prompts
- agent session: system prompt and four tools, then an initial turn plus 5 follow-up turns that
  each add about 1500 words of a project file and continue from the model's own earlier answers,
  64 new tokens per turn, 3 sessions;
  the cache numbers come from the answer's usage (`cached_tokens`) and timings (`prompt_n`)

## Correctness and limitations

Speed suite, plus one recall check (below): these numbers describe the
control-vector-modified configuration (see above) and make no other quality claim.

### Needle recall

`terminal/tools/needle_bench.py` from the repository, run against the same fresh instance right
after the speed suite: a code word hidden in repo text at 10 %, 50 % and 90 % depth, asked with
thinking off, greedy. 6 of 6 found: 27,733–27,734 prompt tokens at "32k", 107,779–107,781 at
"128k" (the script targets 2 % under the label to fit the context). Per-case data:
`needles.json`. This measures recall on these inputs, not overall model quality.
Coding or tool-use quality: not measured. The conversation uses the model's own replies, so
token counts differ a little between runs. No clock/thermal capture in this session; the
2026-11-26 session on the same machine observed 48–54 °C and 2857–2872 MHz under load with no
throttling.
