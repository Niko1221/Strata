# План архитектурной модернизации Strata-Flint

В ходе аудита кодовой базы оригинальной Strata (`src/qwen35/q36_engine.cu`, `src/program/generate.cpp`, `src/core/layer.cpp`, `src/kernels/cuda/kv_stream.cu`, `include/strata/kernels/cpu/pool.hpp`) выявлены ключевые расхождения и механизмы, которые не были перенесены при начальной сборке `strata-flint`.

---

## 1. Выявленные узкие места и отсутствующие механизмы Strata

| № | Механизм Strata | Текущее состояние в Flint | Влияние на систему |
|---|---|---|---|
| **1** | **Batched Tensor Core Attention** (`cublasGemmStridedBatchedEx`) | Использовался Split-K matvec (`k_flint_attn_part` + merge) даже для префилда $T \ge 512$, тратя 320 мс/чанк | Главный тормоз префилда: сдерживал скорость на уровне ~770–900 tok/s вместо 1500–2000+ tok/s |
| **2** | **3-уровневый KV Cache** (32K VRAM Ring + 256K Host RAM + SSD) | KV выделялся статически в VRAM на весь `max_context`, вызывая VRAM OOM при контексте > 32K | Блокировка масштабирования контекста до 256K на 16GB GPU |
| **3** | **CUDA Graph Replay для Decode** (`cudaGraphExec_t g1`) | Объявлен в `Engine`, но не захватывался; каждый токен делает ~500 вызовов кернелов | Оверхед Windows-драйвера CPU на каждом шаге генерации |
| **4** | **CPU Pool Fallback** (`ExpertPool`) | При нерезидентном эксперте (`slot_of < 0`) токен терял эксперта: `if (slot_of < 0) continue;` | Риск потери качества модели при `margin < 1.0` |
| **5** | **Профилирование и адаптивный кэш экспертов** | Эксперты загружаются строго $0..N$; нет ротации по ходу длинного диалога | Падение хитрейта VRAM в длительных беседах |
| **6** | **MoE Prefill MMQ** (`MMQ::Product`) | Эксперты в префилде считаются через `native_expert_grouped` с мелким ncols | Повторное считывание весов экспертов из VRAM при $T \ge 512$ |

## 2. Пошаговый план реализации

### Этап 1: Batched Tensor Core GEMM Attention в префилде
1. **Кернел распаковки KV**:
   - `k_flint_kv_unpack_f16`: быстрая распаковка блоков Q8_0 в полуторочные буферы `k16` и `v16` на GPU (<0.005 мс).
2. **Тензорный расчет скоров и значений**:
   - Запуск `cublasGemmStridedBatchedEx` для $S = Q \cdot K^T$ (FP16 Tensor Cores с аккумуляцией FP32).
3. **Каузальный Softmax со скользящим окном и синками**:
   - `k_flint_attn_softmax16`: расчет Softmax по строкам в FP16 с соблюдением маски $pos - 512 \le p \le pos$ и фиксацией постоянных синк-токенов ($p < 4$).
4. **Тензорная проекция выхода**:
   - Запуск `cublasGemmStridedBatchedEx` для $O = \text{Softmax}(S) \cdot V$.
5. **Ожидаемый результат**:
   - Снижение времени обработки внимания с 320 мс до <5 мс на чанк 512 токенов.
   - Разгон скорости префилда до **1,500 – 2,000+ токенов/сек**.

---

### Этап 2: 3-уровневый KV Cache (VRAM 32K Ring + 256K Host RAM + SSD)
1. **Кольцевой буфер VRAM (Hot Ring)**:
   - Лимит видеопамяти под KV: `--kv-resident 32768` (~1.63 GiB).
   - Фиксация постоянных синк-токенов в позициях $0..3$.
   - Циклическая адресация для $pos \ge 4$: `vram_pos = 4 + ((pos - 4) % (kv_resident - 4))`.
   - Так как окно внимания Flint составляет 513 токенов, буфер в 32,768 позиций с 60-кратным запасом сохраняет все нужные слои.
2. **Хостовый буфер полного контекста (Pinned Host RAM)**:
   - Выделение через `cudaHostAlloc` на полный контекст до 262,144 токенов (~13 GiB DDR5 RAM).
   - Фоновая DMA-синхронизация записанных Q8_0 блоков из VRAM в Host RAM.
3. **Ожидаемый результат**:
   - Поддержка `--max-context 262144` без риска исчерпания VRAM на видеокартах 16GB.

---

### Этап 3: CUDA Graph Replay для шага декодирования ($T=1$)
1. Захват первого шага генерации в `cudaGraph_t` через `cudaStreamBeginCapture`.
2. Инстанциация `cudaGraphExec_t g1`.
3. Реплей графа на каждом токене через `cudaGraphLaunch(g1, st)` вместо 500 вызовов кернелов.
4. **Ожидаемый результат**:
   - Устранение задержек хоста и прирост скорости decode на 5–10%.

---

### Этап 4: Защита экспертов (CPU Pool & Adaptive Cache)
1. Подключение `strata::kernels::cpu::ExpertPool` для фонового расчета нерезидентных экспертов на ядрах процессора при `margin < 1.0`.
2. Включение счетчиков обращений к экспертам для динамического адаптивного свопа горячих экспертов в VRAM.
