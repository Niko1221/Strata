# gfx1101 support plan (gfx1100 → gfx1101)

Extending the experimental AMD HIP backend from RX 7900 XTX/XT (gfx1100) to the
gfx1101 family (the dev box here: RX 7800 XT, device ID 0x747e, 220 W,
reporting gfx1101 / 60 CU / wave32 / 64 KiB LDS / 16 GiB VRAM; rocm-smi and
KFD sysfs).

## Analysis: what gfx1100 actually gates

The backend is ~48 CUDA-shaped `.cu` kernels re-tagged as HIP
(`cmake/hip_backend.cmake:44-51`) plus compat shims in
`include/strata/hip_compat/`. The code is arch-portable by construction;
exactly five places are gfx1100-specific:

1. `cmake/hip_backend.cmake:6-9` — `FATAL_ERROR` unless
   `CMAKE_HIP_ARCHITECTURES` is exactly `gfx1100`.
2. `src/core/device.cu:68` — runtime
   `strncmp(gcnArchName, "gfx1100", 7) != 0 || warpSize != 32` → throw.
3. `setup.py:652` `AMD_ARCHS = ("gfx1100",)` (+ `amd_problem()`, L691-695) —
   Python installer allowlist.
4. `include/strata/hip_compat/intrinsics.hpp:18` — `#if defined(__gfx1100__)`
   selects RDNA3 `__builtin_amdgcn_sudot4` fast `__dp4a`; otherwise a scalar
   fallback compiles silently (correct but slow).
5. `tools/hip/gfx1100-hipblaslt-*.txt` — calibrated hipBLASLt solution table,
   header-scoped to arch+version (`src/prefill/gemm.cu:121-156`); missing or
   mismatched table → graceful fallback to hipBLASEx.

Cosmetic: `CMakeLists.txt:36` (option text), `src/core/device_main.cpp:37`
(selftest print), `docs/AMD_HIP.md`, `docs/AMD_HIP_PERFORMANCE.md`.

Arch-neutral (no change needed): all `__HIPCC__` branches (QSA FP32 fallbacks,
`fused_gr.cu:183` `TILE=1280` for 64 KiB LDS, wave-majored `dim3(32,n)`
blocks); the generic `gcnArchName` parser in `ggml_cuda_host.cu:33-56`;
`setup.py:674` sysfs detection (already emits `"gfx1101"`); `setup.py:1838`
table glob (`{arch}-hipblaslt-*.txt` auto-picks a gfx1101 table);
`tune_hipblaslt.cpp` (arch-agnostic, writes `tools/hip/gfx1101-...`).

Tuning-table note: the existing table is 30 rows = 15 shapes × 2 token
buckets (4096/8192). The tuner's *default* shape list (3 shapes) does not
cover the two rows the test suite requires (`bf16 48 2560 96 4096`,
`f16 512 2560 512 4096`); the original calibration used a custom shapes file
reconstructable from the table's rows.

## Plan

**Phase 1 — open the gates (the only real code changes).**
Allow-list `STRATA_HIP_ARCHS = (gfx1100, gfx1101)` — structured so future
arches are one-line additions (gfx1102 not claimed, not validated).

1. `cmake/hip_backend.cmake` — allow-list check replacing the strict
   `STREQUAL "gfx1100"`; update comment and status message.
2. `src/core/device.cu:68` — accept `gfx1100` or `gfx1101`, keep the
   `warpSize != 32` rejection; update error text.
3. `include/strata/hip_compat/intrinsics.hpp:18` —
   `defined(__gfx1100__) || defined(__gfx1101__)` so RDNA3 `sudot4` stays
   active (both RDNA3 ISA; `__has_builtin` guard retained).
4. `setup.py` — `AMD_ARCHS`, `AMD_NAMES`, refusal messages
   (L647, L691-695, ~L1543, L1555).
5. Cosmetic: `CMakeLists.txt:36`, `src/core/device_main.cpp:37`, docs titles.

**Phase 2 — build & verify via `./setup.sh --backend hip`.**

6. After Phase 1, run setup: KFD detection → `gfx1101`, system ROCm at
   `/opt/rocm`, compile with `-DCMAKE_HIP_ARCHITECTURES=gfx1101
   -DSTRATA_PREFILL_MMQ=ON`, stamp `engine/`.
7. `strata-device --selftest` → gcnArchName gfx1101, wave32, `FITS` against
   16 GiB (the one real sizing risk vs the 24 GiB baseline).
8. Separate test build with `-DSTRATA_BUILD_TESTS=ON` → full `ctest`;
   `hip_prefill_hipblaslt_gemm` skips until Phase 3.
9. Smoke-run the downloaded Coder IQ1_M model end-to-end.

**Phase 3 — gfx1101 hipBLASLt calibration table.**

10. Build `tune_hipblaslt`; reconstruct the 15-shape list from the gfx1100
    table rows (n∈{1,4,48,128,320,512,640,2560,6144,10240,12288},
    k∈{320,2560,6144,10240} combos, ldy=n, T=4096/8192); run →
    `tools/hip/gfx1101-hipblaslt-<version>.txt` at this ROCm's
    `hipblasLtGetVersion`.
11. Re-run ctest with `STRATA_HIPBLASLT_TUNING` → the two focused rows must
    exist; `setup.py:1838` wires the table up automatically on reinstall.

**Phase 4 — docs.**

12. `docs/AMD_HIP.md` scope → "gfx1100 / gfx1101 (RDNA3, wave32)";
    `docs/AMD_HIP_PERFORMANCE.md` notes calibration is gfx1100-scoped.
    Optionally capture `benchmarks/…-gfx1101.json` via
    `tools/hip/bench_prefill.py` afterward.

## Risks / expectations

- 16 GiB VRAM vs the 24 GiB baseline: the engine's `plan.vram_budget` FITS
  check (`device_main.cpp:51`) decides; a sizing question, not an arch one.
- 60 CU vs the XTX's 54 CU — expect different (not directly comparable) perf
  numbers; do not reuse the gfx1100 benchmark claims.
- Without a gfx1101 table, prefill uses the hipBLASEx fallback — functional
  but slower than the calibrated path.
