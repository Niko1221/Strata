# Super-chunk префолла: слой-мажорный обход (q36)

Референсная машина: RTX 3060 Ti 8 ГБ, 32 ГиБ RAM, i7-4790K, KAT IQ4_XS (qwen35moe),
KV q4_0, память +1003 МГц. Ревизия этого PR.

## Зачем

На промпте 96k движок гоняет 805.9 ГиБ экспертных байтов по PCIe: каждый чанк
prefill 2048 токенов заново грузит экспертов всех 41 слоя. При `--prefill 2048` промпт
96k — это ~43 чанка, то есть эксперты каждого слоя стейджатся ~43 раза. На hybrid-раскладке
MoE prefill упирается в байты, а не в матмулы.

## Что сделано

`STRATA_Q36_SUPER_CHUNK=N` (1..64, по умолчанию 1 — старый путь) собирает N чанков
в супер-чанк и идёт по модели **слой-мажорно**:

1. embed всех T = N×2048 строк в `xsuper`, `k_rms` → `hsuper`;
2. для каждого слоя: один `stream_take`, затем для каждого под-чанка копия
   `hsuper[off] → h`, вызов `layer(T=2048)` и копия `h → hsuper[off]`, затем `stream_done`;
3. позиции под-чанков — device-массив `pos_super` (не `hpin`: асинхронная копия
   гонится с записью с хоста);
4. MTP идёт по тем же под-чанкам: семена строк q — `hsuper[q−1]`, для первой — `hlast`;
   super-путь разрешён и при `mtp_d > 0` (этап 2);
5. `on_chunk` и смена окна — только на границах супер-чанка.

Единственная правка в `layer` — новый параметр `stream_base`: если задан, эксперты слоя
уже застейджены вызывающим, и `stream_take`/`stream_done` не зовутся (взводится только при
активном потоке экспертов: `main_hybrid && use_mmq`). Буферы остаются размера чанка;
`xsuper` + `hsuper` растут на 32 МиБ каждые 2048 токенов (оба держат T×N float),
поэтому `super_n` ограничен 8 (256 МиБ), выбранный размер пишется в лог.

## Декод-шаг 1 после супер-чанка (#202)

Проверка: состояние после промпта и первый декод-шаг при N=1 и N=4. Стенд: `main` bedae61d + dump-патч,
KAT IQ4_XS, KV q4_0, промпт T=4600 при ctx 8192. Запас контекста важен: прежняя мерка 4096+2 при ctx 4096
писала шаг 1 за буфер и могла сама давать расхождение. Скрипты: `dump_super_4k.py` (дампы и полные логиты),
`compare_state_dump.py` (SHA/cos блоков), `gen_compare.py` (логиты по шагам).

| Проверка | Результат |
| --- | --- |
| `S`/`conv` всех 30 GDN-слоёв после промпта | SHA совпал, cos 1.000000 |
| `hlast` | совпал |
| KV (`kq`/`vq`) | побитово |
| N=4 против N=4 (два прогона) | логиты шага 0 и шага 1: max_abs 0.0 |
| N=1 против N=4, шаг 0 | max_abs 0.0 |
| N=1 против N=4, шаг 1 | max_abs **0.181–0.231**, argmax совпал: **0.181** при `STRATA_Q36_FIXED_SLOTS=1`, **0.231** без него |
| needle на super (96k/78k) | 3/4 |

Вывод: состояние после промпта идентично (H1 — S/conv — исключена), декод детерминирован (N=4 против N=4 —
0.0). Остаточная разница N=1/N=4 — только порядок сумм на шаге 1: разные пути стейджинга экспертов дают
другой порядок сложения, argmax тот же. H2 (план экспертов) не объясняет: при фиксированном плане
(`STRATA_Q36_FIXED_SLOTS=1`) разница 0.181, а не 0. Это не дефект super-chunk; отдельной правки не требуется.
Бит-в-бит между N=1 и N=4 не является целью (порядок сумм намеренно разный), качество подтверждает needle 3/4.

Промпт 86 589 токенов на 96k (ctx 98 304), 111 831 на 128k (ctx 131 072), prefill 2048,
MTP 0, att 256:

| --- | ---: | ---: | ---: | --- | --- | --- |
| 64k | 728.6 | **913.8** | +25 % | 18.7 → 19.4 | 84.4 → 67.3 | — |
| 96k | 800.9 | **1024.0** | +28 % | 16.7 → 17.2 | 108.1 → 84.6 | 19 → 17 |

## Профиль 96k (STRATA_Q36_PROFILE=1)

| компонент | N=1, мс | N=4, мс | Δ |
| --- | ---: | ---: | --- |
| total | 127 021.8 | 103 174.2 | −18.8 % |
| attn | 61 372.3 | 60 958.8 | 0 |
| gdn | 15 393.1 | 15 408.7 | 0 |
| moe | 49 518.9 | 23 336.6 | −52.9 % |

MoE раскладывается на ~35 с копий и ~15 с CPU-счёта при N=1 и ~8.7 с копий при N=4.
Остаточный потолок при N→∞: attn 61 + gdn 15.4 + счёт 14.6 ≈ 93 с (≈930–950 pp).
H2D выбран до конца, следующий рычаг — prefill-attention (60 % времени).

## Цена и ограничения

- Отмена и смена окна откладываются до границы супер-чанка: до ~36 с на 96k при N=4;
  при нескольких параллельных сессиях их окна декода подаются только на этих границах.
- Память: `xsuper` + `hsuper` занимают 32 МиБ на 2048 токенов (`super_n` ограничен 8);
  на 128k число слотов падает 7 → 5.
- MTP на супер-чанке стоит ~11 % pp (1024 → 911 на 96k): MTP-блок идёт по всем строкам,
  а его гибридный слой стейджится на каждый под-чанк, поэтому экономия H2D при N=4 —
  3.73× вместо 4×.
- Дизайн обещал 2130–3020 pp при N=4, замер дал 1024: доля копий в prefill ниже оценки
  модели (p≈0.25), а CPU-счёт и attention доминируют.

## Как включить

```
set STRATA_Q36_SUPER_CHUNK=4
strata-q36.exe --native <модель> --max-context 98304 --prefill 2048 --mtp 0 ...
```

Без переменной (или при 1) работает старый путь бит-в-бит; откат — снять переменную.
