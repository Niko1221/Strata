# Community benchmark on RTX 5060 Ti 16 GB — plus a helper-cache A/B with an RTX 3060 Ti 8 GB card (WSL2)

Measured on 2026-11-01 by `@xss1992`. What was tested: the tuned single-card
config of Qwen3.8-Flash-Next **UD-Q4_K_XL** at 256 K context on a 16 GB Blackwell card under
**WSL2**, and the second-card **helper expert cache** (`--expert-cache-device1` +
`--remote-expert-opt`) on the same box. Main result beyond the speed numbers: **the helper
cache measures as a net loss on this machine**, and the reason is specific (all experts are
already RAM-resident; the host path is already the fast path). Main limitation: measurements
were taken on a live server hosting an interactive session, not via `strata bench run`, so
they are labelled non-standard.

## Hardware and software

- GPU 0: RTX 5060 Ti 16 GB (sm_120), GPU 1: RTX 3060 Ti 8 GB (sm_86, idle in all final runs);
  CPU: Intel i9-14900KF; RAM: 128 GB DDR5 (WSL limit 110 GiB); storage: NVMe.
  PCIe link: not readable from WSL sysfs; the engine's own measurement is in `data.csv`
  (`the link 24.4 GB/s`, CPU pool `34.0 GB/s` of expert bytes).
- OS: Windows 11 host, Ubuntu 24.04 on WSL2 (kernel 6.18.33.2-microsoft-standard-WSL2);
  driver 610.88; engine build `linux-x86_64-cuda-cuda13`.
- Strata 0.2.9 / Control 0.1.55 / engine 0.1.55 (release binaries).
- Background workload: an always-on interactive session served by the same engine during the
  A/B runs (this makes the numbers "busy-machine" numbers, not idle-box numbers).

## Model and configuration

- Model: Unsloth `Qwen3.8-Flash-Next-UD-Q4_K_XL` (4-shard GGUF), expert pack `unsloth-ud-q4_k_xl`,
  expert-profile (24,576 ranked pairs) generated by an earlier terminal session.
- Context 262,144; `--kv int8 --kv-grow`; `--expert-cache 3400` requested, engine kept
  **3,120 slots** at runtime (auto-fit); `--expert-cache-per-layer`; `--vram-reserve-mib 128`;
  `--conversation-cache-mib 16384`; `--adapt-min-gain 3.0`.
- Speculative: `--spec 4 --spec-min-p 0.85`, MTP runtime adapter (`--mtp .../mtp/rt`).
- Env: `STRATA_HC_Q8=1`, `STRATA_ROUTE_TAIL_SKIP=0`, `STRATA_ROUTE_PRIOR=1.0`,
  `STRATA_PREFILL_CPU_SHARE=auto` (`..._MAX=1024`). Vision encoder on CPU.
- Resident experts ≈ 71.7 GiB in RAM (of the ~88 GiB expert set); cache hit share 80–94 %
  during real long-context use.

## Method

- Harness: `bench.py` (this folder) — pure-stdlib OpenAI-compatible SSE streaming client;
  unique-nonce word prompts so the prompt cache never serves a repeat; `temperature 0.0`;
  prefill and decode rates read from the engine's own timing lines.
- A/B: the same ~100 K-token prompt sent to the single-card config and to the helper variant,
  identical settings except the two helper flags; single paired runs each (this is noted as a
  limitation — repeat medians were not recorded).
- Helper variant = the config here plus `"env": {"CUDA_VISIBLE_DEVICES": "0,1"}` and
  `--expert-cache-device1 <slots> --remote-expert-opt` in `"args"`; the second card is only
  visible to the engine when the launch config's `env` overrides `CUDA_VISIBLE_DEVICES`
  (the server derives it from `"gpu"`, which must stay `[0]` so no `--layer-split` is added).

Memory and cache state:

| Configuration | Main-card VRAM | Main expert cache | Helper cache |
| --- | ---: | ---: | ---: |
| Single card | ~15.5 GB used | 3,120 slots | — |
| Helper variant | ~15.2 GB + 7.8 GB (helper) | 2,016 slots (-35 %) | 2,185 slots / 6.37 GiB |

Why the helper loses on this machine — the documented wins (dual 4090 +63 %, 5090+4090
+28–63 %) assume misses take a slow path (low RAM bandwidth, or experts spilling to SSD).
Here every expert byte is already in fast RAM: the host path measured 34 GB/s of expert
bytes vs a 24.4 GB/s link, so moving hot experts to the second card swaps a faster path for
a slower one, and additionally costs 35 % of the primary cache (to pinned/registered helper
space), per-layer cross-card staging (~220 ms + 50 ms per request in the logs), and a
prefill penalty (prefill waits on the helper). Conditions where the helper should win:
primary-cache hit share below ~60 %, low memory bandwidth (e.g. dual-channel DDR4), or
experts spilling to SSD — none of which apply here.

## WSL2 notes

- With a helper active, only 8 GiB of the host expert arena is registered with CUDA under
  the WDDM host (`STRATA_ARENA_PIN_GIB` overrides); explicit helper slot counts are safer
  than `auto` there.
- The idle helper card still holds ~920–1,160 MiB for the driver/WDDM reservation.
- Mixed-arch visibility (sm_120 + sm_86) means per-arch default tables are not applied to
  the helper card's arch (see #3313); this run made no attempt to force them.

## Correctness and limitations

- No needle/recall run on this build; the box serves real long-context agentic work daily
  at 256 K without observed recall failures (anecdotal).
- Single paired run at one prompt length; prompt token count approximated from duration x
  rate; TTFT and generated-token counts not recorded; machine not idle; not
  `strata bench run` (standard protocol), so treat as a busy-machine community report.
- Earlier findings on engine 0.1.48–0.1.49 (layer-split OOM on the 8 GB card with 0.71 GiB
  free, peer tier needing a non-empty primary cache) are unchanged in spirit and documented
  in the linked issues.
