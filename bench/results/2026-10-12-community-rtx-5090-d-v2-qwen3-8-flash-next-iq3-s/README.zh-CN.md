# NVIDIA GeForce RTX 5090 D v2 社区基准测试

[English](README.md) · **简体中文**

2026-10-12 用 `tools/strata_bench.py`（套件 1，每项 3 轮，取中位数并给出范围）实测，另加仓库自带
`tools/needle_bench.py` 的 32K 长文检索检查（**3 根"针"全部找到**，深度 10/50/90；数据见 `needles.json`）。
速度均为引擎自报计时；首 token 时间由客户端经 HTTP 实测。

这是 **RTX 5090 D v2**（24 GB 中国特供版）的首份社区报告。

## 硬件与软件

- GPU 与显存：NVIDIA GeForce RTX 5090 D v2，显存 24,455 MiB，功耗上限 546.25 W（`nvidia-smi`）；
  PCIe Gen 4 x16，引擎启动时的传输探测报告 28.4 GB/s 主机到设备（`pcie_frac 0.55`）
- CPU：AMD Ryzen 5 5600X 六核处理器（6 核 12 线程，无 AVX-512：专家内核跑在 AVX-2 上）；
  内存 127.9 GiB（4 x 32 GB DDR4-3600）；存储：金士顿 KINGSTON SNV3S2000G 2 TB NVMe SSD（系统盘）
- 系统：Windows 11 专业版（10.0.26200）；显卡驱动 616.56；CUDA 13（引擎自带的 `cu13` 库）
- Strata：项目 0.1.43，官方 Windows 发行版布局（`START-HERE.bat` 安装，非 git 检出）；引擎 0.1.43
- 后台负载：本次基准压的就是发起它的那个交互式 agent 会话正在使用的服务器（一次只处理一个请求）。
  两轮短聊天排在实时 agent 请求之后，出现 19.4 秒和 23.9 秒的首 token 离群值；解码速度和读 prompt
  速度是引擎自报计时，不受排队影响。没有其他负载在跑。

## 模型与配置

- 模型与量化：`qwen3.8-flash-next-iq3_s` — ISTA-DASLab 对 Qwen3.8-Flash-Next 做的 GSQ-RCO
  **abliterated（去审查版）** IQ3_S（`Qwen3.8-Flash-Next-GSQ-RCO-abliterated-IQ3_S-00001-of-00002.gguf`，
  320,001,536 行的 PLE 表直接从分片 `00002` 读取），原生专家包 `packs/iq3_s`，MTP 草稿层由安装器下载
  （`--mtp mtp/rt`）
- 上下文：262144 token；KV 为 int8；并行槽位：1；视觉开启（GPU 辅助进程，1024 图像 token，预留 1500 MiB）
- 设置：安装器自己的配置，未做改动；测试期间思考（thinking）关闭；温度 0。
  摘自引擎启动日志：专家缓存 `auto` 定为 **5104 槽 / 9.71 GiB 显存**，按画像预填充
  （24576 个排序对），不淘汰；宿主内存中 46.84 GiB 专家区（`cudaHostRegister PORTABLE` 成功，
  大页被拒，用 4 KB 页）；MTP `--spec 4 --spec-min-p 0.5`，草稿头覆盖 106,299 个 token
  （含中日韩的子集）；预填充 `auto`：8,192 token 一块，借用 2187 个缓存槽（4.12 GiB）；
  CPU 专家池：5 个工作线程 + 宿主线程；`STRATA_ROUTE_TAIL_SKIP=7` 开启（默认值）；
  全部加载后显存还剩 905 MiB

## 方法

用 `python tools/strata_bench.py --long` 压一台**已在运行**的 Strata 服务器的 HTTP API；模型加载不计入计时。
先丢弃一次热身聊天和一次 1K prompt。每个 prompt 开头都带唯一标记，所以会话缓存帮不到"读新 prompt"的测试。

- 短聊天：`tools/ab_engine.py` 的三个问题，最多生成 100 个新 token，3 轮
- 4K / 16K prompt：用校准请求定长度的词表，生成 24 个新 token，各 3 个全新 prompt
- agent 会话：系统提示加四个工具，随后 5 轮，每轮追加约 1500 词的项目文件内容，并接着模型自己之前的
  回答继续（模拟 agent 客户端重发会话的方式），每轮生成 64 个新 token，共 3 个会话；缓存数字取自
  应答里的 usage（`cached_tokens`）和计时（`prompt_n`）
- 并发（本次未测）：N 个请求同时发出，总 token 除以突发窗口的墙钟时间，延迟统计覆盖全部请求

## 正确性与局限

未改动的 `tools/needle_bench.py` 在 `32k` 长度下**三根针全部找到**（深度 10%、50%、90%；实际 prompt
长度 32,804-32,805 token；逐请求数据见 `needles.json`）。其中两次 37 秒的运行包含排在上述实时 agent
会话之后的等待；检索检查只衡量这三条输入上的召回，不代表模型的整体准确率。

agent 会话使用模型自己的回答，所以各轮的 token 数会略有出入。机器信息来自服务器、`nvidia-smi` 和
操作系统。速度套件总耗时 139 秒。未测：长输出、采样解码、思考模式、持续满载下的温度表现、并发，
以及推理过程中显存/内存的峰值（上面引擎启动时的数字是静态分配，不是峰值）。
