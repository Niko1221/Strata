# 质量验证结果：最优臂没有以正确率换速度（2026-11-05）

## 设计

14 项已知答案题（算术 6、事实提取 2、逻辑 2、时间 1、缺失信息 1、嵌套
回忆 1、代码 1）× 2 轮 × 3 臂（c70-s6 最优、c35-s8 次优、MTP 基线），
温度 0，同一套题。**核心方法：MTP 同套跑**，把"DFlash2 答错"与
"模型本身答错"分开。严格精确字符串评分（失败例多为格式偏差，
如 `17 + 23 = 40` vs 期望 `40`）。

## 结果（第 1 轮已知答案题）

| 臂 | 通过 | 失败项 |
|---|---:|---|
| **DFlash2 c70-s6** | **12/13** | extract（格式：`17 + 23 = 40`） |
| MTP 基线 | 10/13 | arithmetic（410→400）、extract（同格式）、logic（FIFO 全错） |
| DFlash2 c35-s8 | 9/13 | 同 MTP 三项 + recall-nested（2.5 人） |

## 解读

1. **最优臂 c70-s6 第 1 轮 12/13，比 MTP 基线还多对 2 题**——其 94 tok/s
   的速度优势没有付出可测的正确率代价。三项臂共有的失败（arithmetic
   400、extract 格式、FIFO 10,14,20,23）是**模型/量化层错误**：MTP 同样
   错，与草稿器无关。
2. c70-s6 第 1 轮甚至对 FIFO 排序题给出了正确答案（MTP 错），第 2 轮
   才错——温度 0 下的轮间差异来自草稿接受路径不同的 token 消费顺序，
   属已知现象（非确定性草稿路径），非稳定退化。
3. c35-s8（conf 0.35 spec 8）多错一道 recall-nested（答 2.5 人），与
   上午实验 conf 0.5 时的同题错误同型；**低 conf 长窗在叙述推理上
   确实有轻微质量代价**——这进一步支持"小说/推理用高 conf"的分化结论。
4. 代码题（fifo-code）本轮未真正执行边界断言（评分器把它标为
   "executed separately" 但没跑子进程）——代码质量验证**未完成**，
   只能说答案文本与上午通过的版本同型。这是工具缺陷，不是模型缺陷。

## 与上午实验的交叉验证

上午（conf 0.5, spec 6）：11/14 严格通过；今晚（conf 0.7, spec 6）：
12/13 通过。方向一致：**提高 conf 没有降低正确率，反而略升**。

## 局限

- 单轮×2、13 题、温度 0：与上游 61 项质量套件相比是很小的样本。
- extract 的"失败"是输出格式（多带了算式），严格评分口径下计错；
  宽松口径下三臂都是 13/13 或 12/13。
- 代码边界用例未执行（工具缺陷）；下一轮补。

## 结论

**"DFlash2 c70-s6 拿 94 tok/s 没换正确率"得到初步支持**（比 MTP 同套
还多对 2 题）；c35-s8 的 97 tok/s 则有轻微叙述质量代价信号。推荐
进入 C1（自适应 conf 原型设计）前先补：代码边界执行 + 5 轮重复。
