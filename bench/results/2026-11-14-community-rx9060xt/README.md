## Method

The frozen requests of `bench/prompts/standard-v1` (corpus `e75eff8b9feea04f...`) were sent over loopback HTTP, streaming, one at a time, in this order: 1 warm-up (excluded), 3 repetitions of the short, 4K and 16K prompts, and the twelve sanity checks. Prompt and decode speed are the engine's own `timings`; time to first token is the client's monotonic clock from dispatch to the first nonempty reasoning, answer or tool-call delta. No request was retried. Time after the model loaded: 3 min 52 s.

## Operator notes (not generated by `strata bench run`)

This is a single gaming desktop that also drives its display, so the numbers above are
representative of "the card is shared with a desktop", not of a dedicated inference box.

- **`--vram-reserve-mib 3072`** was kept on for the run (3 GiB held back for the desktop).
  Expert cache: 7.81 GiB / 5,830 slots. The default run left only 750 MiB of VRAM free.
- **Prefill uses plain hipBLAS**: `no hipBLASLt tuning table for gfx1200 with hipBLASLt 100201
  (have: gfx1200-hipblaslt-100202.txt)`. The 4K/16K prompt figures above are therefore *without*
  a gfx1200 tuning table; `tools/hip/tune_hipblaslt` was not run.
- **`--track custom`**: the server was started from `run-iq2_xs.sh` (the setup-written script)
  rather than from an installed profile, so no profile notes were attached.
- **Failed attempts, reported because they mislead if omitted.** The first two runs of the same
  model measured **0.5 tok/s** and died with
  `Unrecoverable native verification failure: verify: timed out at layer 33; its GPU waits were
  released but the GPU did not finish within 5 s (#267)` after 52 and 65 tokens. The engine log
  in that state said:

  ```
  not enough RAM for the expert arena (it needs 37.02 GiB (with the 4.00 GiB the engine's own
  memory and the RAM to keep take on top of it) and this process's memory limit is 4.00 GiB):
  this run reads the experts from the file, like --mmap-experts (slower; the answers are the same)
  ```

  `ulimit` and the cgroup were unlimited (`memory.max = max`, `MemoryMax=infinity`): the 4.00 GiB
  figure came from the launch-time RAM check inside a supervising process tree, not from a hard
  cap. Started detached in its own `systemd-run --user` unit, the same build logs
  `expert arena read through the file cache (buffered)` and `cudaHostRegister PORTABLE ok`, RAM
  settles at ~42 GiB, and the verify timeout disappears — the run above is the detached one.
  So on this machine the `verify: timed out` symptom was downstream of an arena that never
  loaded, not of the HIP build or the target.
- Reproduction status: **measured on the machine described above** (reproduced locally).
